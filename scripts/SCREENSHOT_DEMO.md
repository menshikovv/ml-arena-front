# Локальная витрина для скриншотов

Запуск: `npm run dev:screenshots`.
Только loopback-адрес. Данные находятся в памяти процесса, backend не используется.
Вход выполняется автоматически под вымышленным `demo.alex`.
Режим не включается в production-сборку, даже при `build --mode screenshots`.
Редактирование профиля, реальные отправки, загрузки и административные операции отключены.

## Кадры

- `/competitions/demo-techsmena`: условия активной демонстрационной задачи, NDCG@5, CSV.
- `/competitions/demo-techsmena/leaderboard`: открытая таблица шести тестовых участников и своя строка.
- `/rating?tab=overall&season=demo-autumn-2026`: общий рейтинг платформы, сезон и собственная позиция.
- `/duels/demo-duel/live`: учебный матч с двумя участниками, задачей и таймером.
- `/profile`: верх ML-паспорта собственного тестового пользователя.
- `/profile?direction=ranking`: вкладка «Результаты», затем раскрыть нужную работу для статусов проверки и истории отправок.

Маркировка «Демонстрационные данные» должна оставаться в кадре. Числа не являются реальной аудиторией или результатами пилота.
В паспорте отдельно представлены проверенный официальный результат, официальный результат без проверки кода и результат сообщества. Самозаявленный проект вынесен во внешние достижения со статусом ожидания проверки.

## Отключение

Остановить демонстрационный dev-сервер и запустить обычный `npm run dev`.
Обычные AuthProvider и ProtectedRoute не менялись, поэтому авторизация восстановится автоматически.
Для полного удаления режима удалить `scripts/screenshot-demo.mjs`, этот файл и соответствующий тест; убрать импорт плагина из Vite, команду `dev:screenshots` и условную демо-плашку из AppLayout.
