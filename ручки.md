## 1. Авторизация и регистрация

### POST `/auth/register`

Регистрация нового пользователя.

**Request:**
```json
{
  "email": "user@example.com",
  "password": "strongpassword"
}
```

**Response `201`:**
```json
{
  "user": {
    "id": "usr_abc123",
    "email": "user@example.com",
    "role": "user"
  },
  "token": "jwt_token_here"
}
```

**Ошибки:**
- `409` — email уже зарегистрирован
- `422` — невалидные данные (короткий пароль, невалидный email)

---

### POST `/auth/login`

Вход по email + паролю.

**Request:**
```json
{
  "email": "user@example.com",
  "password": "strongpassword"
}
```

**Response `200`:**
```json
{
  "user": {
    "id": "usr_abc123",
    "email": "user@example.com",
    "role": "user"
  },
  "token": "jwt_token_here"
}
```

**Ошибки:**
- `401` — неверный email или пароль

---

### GET `/auth/me`

Получить текущего авторизованного пользователя. Требует `Authorization: Bearer <token>`.

**Response `200`:**
```json
{
  "id": "usr_abc123",
  "email": "user@example.com",
  "role": "user"
}
```

**Ошибки:**
- `401` — токен отсутствует или невалиден

---

### POST `/auth/logout`

Завершить сессию. Требует авторизации.

**Response `200`:**
```json
{ "success": true }
```

---

### POST `/auth/forgot-password`

Запрос на сброс пароля. Отправляет письмо с токеном на почту.

**Request:**
```json
{
  "email": "user@example.com"
}
```

**Response `200`:**
```json
{ "success": true }
```

> Всегда возвращает `200`, даже если email не найден (защита от enumeration).

---

### POST `/auth/reset-password`

Сброс пароля по токену из письма.

**Request:**
```json
{
  "token": "reset_token_from_email",
  "new_password": "newstrongpassword"
}
```

**Response `200`:**
```json
{ "success": true }
```

**Ошибки:**
- `400` — токен невалиден или истёк

## 4. Сабмиты (Submissions)

### POST `/submissions`

Загрузить решение на соревнование.

**Request:** `multipart/form-data`
| Поле | Тип | Описание |
|------|-----|----------|
| `competition_id` | string | ID соревнования |
| `file` | File | CSV-файл с предсказаниями |

**Response `201`:**
```json
{
  "id": "s1",
  "competition_id": "c1",
  "user_id": "usr_abc123",
  "file_url": "https://storage.../submissions/s1.csv",
  "score": 0.0423,
  "status": "evaluated",
  "attempt_number": 2,
  "created_date": "2026-07-10T14:30:00Z"
}
```

**Логика:**
- Бэкенд загружает файл, запускает evaluation pipeline, вычисляет `score` по `metric` соревнования.
- Проверяет дневной лимит попыток (`max_submits_free` / `max_submits_pro`) по роли пользователя.
- `attempt_number` — порядковый номер попытки пользователя в этом соревновании.

**Ошибки:**
- `429` — превышен дневной лимит попыток
- `422` — невалидный формат файла (ожидается CSV)
- `404` — соревнование не найдено или deadline прошёл

---

### GET `/submissions`

Получить список сабмитов.

**Query params:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| `competition_id` | string | Фильтр по соревнованию |
| `user_id` | string | Фильтр по пользователю |
| `sort` | string | `-score`, `-created_date` |
| `limit` | number | |
| `offset` | number | |

**Response `200`:**
```json
{
  "items": [ /* Submission[] */ ],
  "total": 500
}
```

Вычислённый лидерборд для конкретного соревнования. Лучший результат каждого участника.

**Response `200`:**
```json
{
  "items": [
    {
      "rank": 1,
      "user_id": "usr_xyz",
      "user_name": "DataWizard",
      "user_avatar": "https://...",
      "best_score": 0.0312,
      "attempts": 5,
      "submitted_at": "2026-07-12T18:00:00Z"
    },
    {
      "rank": 2,
      "user_id": "usr_abc123",
      "user_name": "AI_Ninja",
      "user_avatar": "https://...",
      "best_score": 0.0423,
      "attempts": 2,
      "submitted_at": "2026-07-10T14:30:00Z"
    }
  ],
  "metric": "rmse",
  "is_higher_better": false

```

> `is_higher_better` определяется по `metric`: `accuracy`, `roc_auc`, `f1` → `true`; `mse`, `rmse`, `mae` → `false`.

{
  "id": "du1",
  "player1": {
    "user_id": "usr_abc123",
    "user_name": "AI_Ninja",
    "rating": 1580,
    "avatar_url": "https://...",
    "score": null,
    "file_url": null,
    "submitted_at": null
  },
  "player2": {
    "user_id": "usr_opponent",

| `limit` | number | |

---

### PATCH `/duels/:id`

Отправить решение в дуэли. Текущий игрок загружает файл.

**Request:**
```json
{
  "file_url": "https://storage.../submissions/du1_p1.csv",
  "score": 0.89
}
```

**Логика:**
- Бэкенд определяет, какой игрок (player1 или player2) делает запрос.
- После отправки второго игрока — автоматически вычисляется победитель, `rating_change`, оба профиля обновляются.

**Response `200`:** — обновлённый объект дуэли со статусом `completed`

---

## 12. Общие договорённости

### Аутентификация

Все защищённые эндпоинты требуют заголовок:
```
Authorization: Bearer <jwt_token>
```

### Формат ошибок

Единый формат для всех ошибок:
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Email already exists",
    "details": { "field": "email" }
  }
}
```

Коды HTTP:
| Код | Значение |
|-----|----------|
| `400` | Невалидный запрос / токен |
| `401` | Не авторизован |
| `403` | Нет прав |
| `404` | Не найдено |
| `409` | Конфликт (дубликат) |
| `422` | Ошибка валидации |
| `429` | Rate limit (превышен лимит попыток) |
| `500` | Внутренняя ошибка сервера |

### Пагинация

Все списки используют `limit` / `offset`:
```
GET /profiles?limit=20&offset=40
```

Ответ всегда содержит `total` для отрисовки пагинации на клиенте.

### Сортировка

Параметр `sort` — поле, префикс `-` для убывания:
```
GET /profiles?sort=-rating
GET /competitions?sort=-created_date
```

### Evaluation Pipeline (асинхронный)

Загрузка сабмита → файл сохраняется → статус `pending` → evaluation worker вычисляет score → статус `evaluated` (или `error`).

Дуэли: после `evaluated` второго игрока — автоматическое определение победителя и пересчёт рейтинга.

### Рейтинговая система

После каждого соревнования и дуэли пересчитываются рейтинги обоих участников по системе, близкой к ELO. Изменение рейтинга записывается в `rating_history`.
